# AegisAI v0.5.0 — Federated Autonomous Defense

AegisAI v0.5 extends the v0.4 trust fabric from a single-agent authority chain to coordinated, multi-agent cyber-defense workflows.

## New primitives

### Delegation

```aegis
delegate ResponseDelegation from Sentinel to Responder capability propose.firewall ttl 120 issuer "SOC-CA"
```

Delegation is bounded by the source agent's authority, the target agent's deny list, the declared capability, and a maximum TTL of 3600 seconds. At runtime the delegation is encoded in an Ed25519 capability credential containing both `agent` and `delegated_from`.

### Quorum

```aegis
quorum ResponseQuorum for BlockHost approvals 2 from [Sentinel, Responder, Analyst]
```

Only declared members count. An execution naming the quorum is rejected unless the runtime context contains enough approvals.

### Policy federation

```aegis
federation DefenseFederation {
    policies [EvidencePolicy, ConfidencePolicy]
    strategy all
}

federate authorize BlockHost using DefenseFederation
```

Strategies are `all`, `any`, and `threshold`.

### Runtime attestation

```aegis
attestation EdgeRuntime for Responder issuer "Attest-CA" max_age 300 measurement "sha256:runtime-v1"
```

The runtime verifies an Ed25519-signed attestation token against the declared issuer, target, measurement, and maximum age.

### Revocation

The runtime checks revocation information immediately before execution. Authorities can be revoked by declaration name, issuer, key ID, or serialized token/credential SHA-256 digest.

## AIR 0.5

New operations:

- `capability.delegate`
- `coordination.quorum`
- `policy.federation`
- `auth.federated`
- `runtime.attestation`

`action.execute` now carries optional `quorum` and `attestation` references.
